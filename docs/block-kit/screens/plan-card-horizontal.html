Dark is real and shipped, but not a skin — there is no second set of rules behind this panel. The card face is surface, the connectors and the pending ring are surface-inset, success-ink and ink-muted, the labels are ink-muted and success-ink, and the dashed stub is a repeating-linear-gradient in line. Every one of those is a single declaration that resolves to core's own Bootstrap value, so this column is what [data-bs-theme="dark"] makes them, not what the plugin painted. The .theme-dark / body.dark rules that used to produce it were deleted: nothing in Moodle 4.5 through 5.3-dev, and nothing in theme_boost_union or theme_boost_union_fundaseg, has ever emitted either selector.
The pill's hover/focus lift needs no dark rule any more. It is 0 4px 14px var(--block-dimensions-shadow), and shadow is one of the three tokens the plugin does own: rgb(0 0 0 / 10%) light, rgb(0 0 0 / 55%) dark. The hand-written pair — .22 light and .5 dark, the second added because the dark rest shadow was heavier than the light hover value — collapses into that one declaration. The translateY(-1px) is the same in both modes.
Untouched by dark mode: the access pill's 8px radius and 10px offsets, the 32px star and the tag pill colours (plan metadata overrides the #FD7E14 / #212529 default; only the chip's shadow deepens). The completed marker used to sit in that list too, staying #198754 — 2.54:1 on the #343A40 card — and it now flips with the skin to #75B798 (4.92:1), the success tone the label beside it already used.
