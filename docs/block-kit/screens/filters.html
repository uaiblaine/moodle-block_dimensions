Pills are a radiogroup of radios with aria-checked, deliberately not tab/tablist — a tablist would require an associated tabpanel (the renderFilterControls() docblock in amd/src/filters.js). Roving tabindex: the checked radio is the group's only tab stop (tabindex="0"), siblings are -1, arrow keys move within.
Accessible name = type label + the admin's custom-field name, "Filter learning plans — Year"; it falls back to the bare group label when the custom field is undefined (filters.js:239-245).
The platter's seven --dims-tabs-* colour variables — platter fill, item and active-item colour, indicator fill and shadow, both paddle colours — are gone; the base rule's use sites now read --block-dimensions-* tokens directly, so there is no separate dark-mode override left to swap them in (styles.css:1336-1364). The count badge is the same story: it is --block-dimensions-surface under --block-dimensions-ink-muted, edged with a 1px --block-dimensions-ink-muted border (styles.css:1993-2010), flipping on its own where it once had no dark rule at all and sat as a foreign light island on the dark platter. The edge is there because the fill alone stands off the platter at only 1.19:1 in light and 1.41:1 in dark, while the border clears 3:1 against it in light, in dark and on 4.5: 5.38:1 at the lowest as drawn. The active badge inside any checked pill, status pills included, reads --block-dimensions-brand-tint / --block-dimensions-brand-ink, which flip on their own too, and is edged with a 1px --block-dimensions-brand-ink border: on the indicator the tint alone is only 1.33:1 in light and 1.13:1 in dark, and the border is 14.41:1 and 6.33:1 (styles.css:2012-2026).
Same radiogroup, the other radio checked — only one is on FLT-ALL-PILL FLT-INDICATOR
The favourite pill paints its own solid brand-fill background under on-brand-fill text — the site's primary, which does not flip, so it is the same blue in both panels — and when it is checked it covers the indicator sliding underneath; the "Show all" pill has no background of its own and reads as the indicator. The pair only renders when favourites are enabled and the type has at least one (typeFavCount > 0), and for plans only in the active bucket, whose cards alone carry a star. On the plan bar the status pills come first when two buckets qualify; they are drawn in plan-status.html. Counts are per type and are patched in place by updateFavouritePillCounts(), so toggling a star never rebuilds the bar and never steals focus.
Overflowing group — edge fade + both paddles FLT-MASK FLT-PADDLE-L FLT-PADDLE-R
Paddles are mouse-only: aria-hidden="true", tabIndex = -1, localized labels — keyboard users move with arrow keys, which auto-centre the focused radio. Each paddle is 36px + 4px = 40px wide; the mask keeps 40 − 4 = 36px fully transparent behind it and fades in over the next 22px. Reaching an end swaps that side's mask colour to opaque and hides the paddle (:has(.dims-filter-tabs-paddle-hidden)). The indicator sits outside the mask, so it is never faded.
wrapTabsContent() rewrites the radiogroup at init: the buttons move into .dims-filter-tabs-items inside .dims-filter-tabs-mask, then the indicator and the paddle pair are appended as siblings. Roles on the children survive the move, and destroyAll() runs before every re-render so instances never stack up.
Same group, dropdown display mode FLT-SELECT
Admin picks pills or dropdown per tag through the four *_displaymode settings (plan_tag1, plan_tag2, competency_tag1, competency_tag2); anything other than dropdown falls back to tabs. Native <select> with appearance:none and the chevron drawn as two 4px currentcolor triangles, so it follows the control's own text colour and needs no second image in dark. Dropdowns get no platter, no indicator and no paddles: FilterTabsNav only ever touches .dims-filter-tabs.
Clear button — rest and hover FLT-CLEAR
:hover
The button is emitted with style="display:none" and updateClearFilterButtons() reveals it only once that type has an active filter. The whole bar renders twice, once per data-filters-type host (plan and competency), each with its own counts and its own clear button. Hover is the only state that gives the button colour, in either skin — which is why it is drawn twice here.
