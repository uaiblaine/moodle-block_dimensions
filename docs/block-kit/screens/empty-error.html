As-is · light (Boost)
1 · Loading — the block's very first paint · BLK-LOADING
Loading
Server-rendered in the shell and visible before any fetch resolves; afterwards syncLoadingLine() shows it while anything is still on its way and hides it when nothing is. The string is core loading, not a plugin string; only a status bucket loading on its own swaps in a plugin string.
2 · Error — warning alert + Retry BLK-ERROR BLK-ERROR-RETRY
Unable to load competency cards right now. Please try again.
Any rejected fetch reaches here — the first load, a phase-2 load or a status bucket — and so does a failed render. showError() blanks the text, unhides the box, then writes the message on the next frame — a role="alert" that was display:none does not announce reliably otherwise (WCAG 4.1.3). Retry starts a new session, so a response of the old one that lands late is dropped, and it moves a focused Retry's focus to the block's region root before the box hides.
3 · Empty — no active plans BLK-EMPTY-NOPLANS

No active plans at the moment.

Shown only once the session's first dataset has arrived, while the active bucket is on screen and the dataset says hasactiveplans is false (before that, the empty lists mean nothing has been fetched yet, and the block says nothing); it is checked first and returns early, so it wins over the other two messages. The block class pre-empts it: has_content() returns false for a learner with no plan in any bucket, and the block opens on the first bucket that holds one, so this text appears only when the plan list changed between the page load and the web-service call, or when the gate failed open.
4 · Empty — no competencies BLK-EMPTY-NOCOMP

No competencies in your plans.

Shown when both lists are empty with nothing filtered away — the loaded dataset holds no card at all — and no ghost card is on screen. updateEmptyState deliberately stays silent while a ghost card is visible — "no competencies" would be a lie when more are one click away.
4b · Empty — nothing matched BLK-EMPTY-NORESULTS

No results found.

Shown when the search or a filter hides every card while the loaded dataset still holds some: the cards exist, so the message says nothing matched rather than that there is nothing. It is the same resultsnonefound string the polite live region announces for a zero count. Both stay silent, rather than claiming no results, while a group load that could still add cards to the bucket on screen is pending (groupLoadCanAddCards()) — a favourites-only bucket still being topped up, or a competency fetch for the active bucket — so a search typed just as such a load starts does not flash "No results found." before the cards it is waiting on arrive.
5 · Favourite-toggle error — announced, never drawn BLK-LIVE-FAV
Could not update favourites. Please try again.visually-hidden · assertive
Written into the data-fav-status region, blanked then re-set on the next frame so an identical message still fires, and self-cleared after 5000 ms so it does not linger in the AT cursor. Its sibling data-results-status is polite and debounced by 600 ms, on a timer of each block's own, so typing in the search box does not flood a screen reader and two blocks on a page do not cancel each other.
6 · No JavaScript BLK-NOSCRIPT

JavaScript is required to load your competency cards in this block.

Deliberately 1rem, not small: it is the only thing a no-JS user ever sees, so it carries legible size and ≥ 4.5:1 contrast (WCAG 1.3.1, 1.4.3).

GST-ICON · 50px circle, 2px ring GST-TITLE · 1.1rem / 700 GST-SUBTITLE · 0.85rem / 400
The ghost card exists because of two-phase loading: with favourites enabled the first request asks for favourites only, so the ghost card is the invitation to fetch the rest. Its count is totalplans − loaded in phase 1 and total − favourites once the full dataset has arrived. One ghost card per type, each appended to its own grid, and clicking it loads only that group. No ghost card is drawn while favourites are disabled, so when a response says an admin has disabled them mid-session, both favourites filters are dropped and the rest of any list still at phase 1 is fetched, rather than leaving the favourites alone on screen with nothing to reach the others.
7b · Ghost card, hover / focus GST-CARD
Hover recolours border, circle and title to the accent and lifts the shell by 2px; :focus-visible draws the 2px focus-ring outline at a 2px offset. Reduced motion drops both the transition and the lift; high contrast forces a 3px currentColor border; print hides the ghost card entirely. The kit grid uses a 205px minimum so both cards fit the panel — the shipped grid is repeat(auto-fill,minmax(min(19rem,100%),1fr)) at a 1rem gap, the floor carried in --dims-card-track-min.
