One focus indicator ships now, and it is not a colour choice. Every focusable control in the block draws the same shape — outline: 2px solid var(--block-dimensions-focus-ring); outline-offset: 2px — with exactly two documented exceptions, the filter tab and the sliding indicator, which draw the identical ring at outline-offset: -2px because their platter is overflow: hidden and would clip an outset one. One element takes focus without being a control: when a focused Retry starts a new load, focus moves to the block's own role="region" root, which carries tabindex="-1" only until focus leaves it. .block-dimensions-content:focus-visible gives it this same ring (styles.css:2214-2219), so the browser's default indicator never shows there. Nothing draws a focus indicator with a box-shadow any more. That is the reason the 4px brand glow and the filter pill's inset ring are gone rather than recoloured: a box-shadow is not painted at all under forced-colors: active, so a control whose only focus signal was one had no indicator in Windows High Contrast Mode. The card's ring also came down from 3px to 2px, because two ring widths on one page read as a drawing error rather than as two meanings. The ring has no dark restatement, and that is the point. --block-dimensions-focus-ring chains --bs-emphasis-color, which core flips: #000 on the light page (21.0:1 against the card face), #fff on the dark one (16.2:1), #343a40 on Moodle 4.5 through the --gray-dark rung (11.5:1). It deliberately does not chain --bs-focus-ring-color, which core fails to flip — that value measures 1.02:1 on the dark page. Historically this was four different light blues (#005fcc, #1a73e8, #0a58ca, #1765cc) with a fifth in dark, then one migrated blue #0f6cbf that eleven of the thirteen indicators kept on a dark surface at 2.15:1. Both stages are recorded in token-migration.md. A brand colour cannot carry a 3:1 obligation the site owner picks the value for, which is why the ring is now an extreme rather than an accent.

prefers-contrast: more STA-CONTRAST

  • The query asks for more, the raised-contrast value Media Queries Level 5 defines. Until 2026-09-23 every block asked for high, which is not a value of the feature, so the browser evaluated it as false and none of the remedies below had ever applied. card_layout_test now fails on an undefined value.
  • Every extreme in this block is now a token, and that is the whole repair. It used to paint #000 borders and outlines with no dark counterpart, so a user on dark plus high contrast got black on a dark card. The borders that name an extreme now name ink-strong (--bs-emphasis-color: #000 light, #fff dark), so the block flips with the page like the rest of the file.
  • Both cards take border: 2px solid ink-strong and a title in color: ink-strong, from one block that follows both cards' own rules; card_layout_test pins that the two card shells share it (the plan card kept its 1px line border here, 1.30:1 in light, until 2026-09-23). The card's focus ring is not restated here any more: the base rule already draws the same 2px ink-extreme outline, and a verbatim duplicate is how the next reader concludes the two must differ for a reason nobody wrote down.
  • Both card gradients, an admin's custom fill included, still flatten to a literal #6c757d, and that literal is deliberate. A flat fill in the image slot has to separate from the card face in both modes at once, so it can be neither extreme: #6c757d is 4.69:1 on the light card face and 3.45:1 on the dark one. A token that flipped would turn the image area light on a dark page and invert the card. Nothing in that slot carries meaning — the title, tags and pill all paint their own ground.
  • Access pill, tags, favourite star, clear button and ghost card thicken to currentColor, which needs no token: it is already whatever ink the element inherited. The access pill trades its shadow for that border, and keeps it off while its card is hovered or focused too: the lift rule outranks the swap, so a second override repeats the lift's own selectors. The select goes 2px solid ink-strong rather than #000, because it sits on the page in both modes.
  • Filter pills gain 2px solid transparent; the active pill takes border-color: focus-ring, the sliding indicator outline: 2px solid focus-ring; outline-offset: -2px, and the active favourite pill 2px solid ink-strong — the border separates a filled pill from the page, so it follows the page.
  • A separate forced-colors: active block now exists, and it is not the same thing. Under Windows High Contrast Mode the browser substitutes its own palette for every background-color, so the white sliding indicator and the filled active pill both flatten to the same Canvas as their neighbours and the selected filter stops being distinguishable (WCAG 1.4.1). An outline is the fix precisely because outline is remapped there, while a background is overwritten and a box-shadow is not drawn at all.

prefers-reduced-motion: reduce STA-MOTION  ·  print STA-PRINT

  • Reduced motion zeroes every transition (card, access pill, filter pill, select, indicator, paddles, clear button, favourite star, ghost card, the mobile filter host and its toggle) and every transform: card hover, the access pill's translateY(-1px), star hover and :active, ghost hover and :active, and the trail marker's scale(1.2) all become none. Colour and shadow changes survive, so every state stays distinguishable without movement.
  • Print hides the access pill, the tag row, the favourite star, the whole filter bar and the ghost card; both cards drop their shadow, force border: 1px solid #000 and set break-inside: avoid, from one block shared by the two card shells; both gradients flatten to #ced4da.
  • Every literal in a print block is deliberate and mode-invariant. Paper is white whatever the screen is doing, and data-bs-theme stays on the html element while printing — so ink resolved through a mode token would print #dee2e6 on white from a dark page. This is the one place in the file where a hardcoded colour is the correct answer.
  • The gradient's print rule no longer needs !important. The admin-chosen fill moved off the inline style attribute and onto a .has-custom-bg class reading a custom property, so the print and high-contrast overrides win at equal specificity instead of fighting an inline declaration — which is also what let the last !important leave the file, since Moodle's stylelint forbids it.
  • The section header prints as solid #000: it clears background-image and resets -webkit-text-fill-color to currentcolor first, because the base rule's transparent fill beats a bare color.
  • What print does not hide: the trail, the section header, the card title and the competency count — which is the intended paper artefact.
