# Field map — `BLK` / `FLT` / `GST` / `RSP` · Block shell, filter bar, ghost card, responsive

> **Line citations, 2026-09-05.** The dark-mode/token rewrite of 2026-09-05 moved about 1400 lines
> of `styles.css`. Every `styles.css:NNN` reference below has since been re-derived against the
> rewritten file: most now cite the same rule at its new line number, and the handful anchored to a
> rule the rewrite deleted outright (a dead `.theme-dark`/`body.dark` selector, the removed
> `@container` block) now cite the current token-driven declaration that replaced it, or a banner
> name where a section rather than one rule is the honest anchor. `mustache:` and `js:` citations
> were never affected.


The block shell is the only server-rendered part: `block_dimensions::get_content()` builds the
`summary` renderable, `summary::export_for_template()` exports **labels and flags only**
(`labelsjson`, `filtersettingsjson`, `showheading` / `showsearch` / `showsectionheaders`,
`favouritesenabled`), and `summary.mustache` emits an empty skeleton. Everything inside it is
rendered client-side by `amd/src/filters.js` from **one** call to
`block_dimensions_get_block_dataset`; `amd/src/state.js` holds the pure filter/search state and
`amd/src/filter_tabs_nav.js` turns each pill group into a scrollable platter. The filter bar is
**not** a template at runtime — it is string-concatenated in `renderFilterControls()`
(`filters.js:67-198`); `templates/filters.mustache` is a documentation-only mirror whose edits have
no effect. Visual replica: the `screens/` files that coin the `BLK-*` (shell + states), `FLT-*`
(filter bar), `GST-*` (ghost card) and `RSP-*` (responsive) badges.

**Settings affecting this screen:** `show_heading` (the "My competencies" h2; unset counts as on),
`hide_block_title` (blanks the *block frame's* own title in `block_dimensions::specialization():57-61`,
independent of `show_heading`), `enable_search` (the whole search row **and** the mobile filter
toggle that lives in it — default off), `enable_section_headers` (both two-line h3 group titles —
default off), `enable_favourites` (star buttons, both pills, the counts and the ghost card;
always read through `dataset_provider::is_favourites_enabled()`, never the raw config, so a fresh
site does not disagree with the web service), `enable_plan_tag1_filter` /
`enable_plan_tag2_filter` / `enable_competency_tag1_filter` / `enable_competency_tag2_filter` (each
switches one filter group on, and it still renders nothing if the loaded cards carry no values for
that tag), and `plan_tag1_displaymode` / `plan_tag2_displaymode` /
`competency_tag1_displaymode` / `competency_tag2_displaymode` (`tabs` — the scrolling pill platter —
or `dropdown`, the native select; anything else falls back to `tabs`). `plancard_layout` and
`enable_trail_links` reach only the card surfaces and are documented with those maps.
