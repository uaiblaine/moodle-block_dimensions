# Field map — `BLK` / `FLT` / `GST` / `RSP` · Block shell, filter bar, ghost card, responsive

> **Line citations, 2026-09-24.** Every `file:line` reference below — `styles.css`,
> `summary.mustache`, the three AMD modules and the PHP classes — was re-derived against the working
> tree on 2026-09-24. Where a section rather than one rule is the honest anchor, the citation is a
> banner name instead of a line range. Nothing pins these numbers: an edit to a cited file can move
> them.


The block shell is the only server-rendered part: `block_dimensions::get_content()` builds the
`summary` renderable, `summary::export_for_template()` exports **labels and flags only**
(`labelsjson`, `filtersettingsjson`, `showheading` / `showsearch` / `showsectionheaders`,
`favouritesenabled`, `isbs4`), and `summary.mustache` emits an empty skeleton. Everything inside it
is rendered client-side by `amd/src/filters.js` from calls to `block_dimensions_get_block_dataset`
— one on load, then one per card group a favourites-only first load left short and one per status
bucket on its first visit; `amd/src/state.js` holds the pure filter/search state and
`amd/src/filter_tabs_nav.js` turns each pill group into a scrollable platter. The filter bar is
**not** a template: it is string-concatenated in `renderFilterControls()` (`filters.js:182-297`),
the only definition of its markup, whose docblock says why every pill set is a radiogroup rather
than a tablist. Visual replica: the `screens/` files that coin the `BLK-*` (shell + states), `FLT-*`
(filter bar), `GST-*` (ghost card) and `RSP-*` (responsive) badges.
