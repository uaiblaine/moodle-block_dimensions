# Field map — `PLN` / `PLN-H` / `CMP` · Plan cards, competency cards and the trail

> **Line citations, 2026-09-23.** Every `file:line` reference below — `styles.css`, the two card
> templates, `filters.js`, `dataset_provider.php` and the other PHP files — was re-derived against
> the working tree on 2026-09-23. Where a section rather than one rule is the honest anchor, the
> citation is a banner name instead of a line range. Nothing pins these numbers: an edit to a cited
> file can move them.


The two card types are the whole visible payload of the block. Neither is server-rendered: the shell
`summary.mustache` ships only labels and config, `amd/src/filters.js` calls
`block_dimensions_get_block_dataset`, and `renderCardItem` (`filters.js:348-372`) renders
`block_dimensions/plan_card` or `block_dimensions/competency_card` through `core/templates` into an
`<li>` it builds itself. Every field in the three tables below comes out of
`classes/local/dataset_provider.php` — `build_plan_card()` (`:824-907`) and
`build_competency_card()` (`:1094-1143`), with the four favourite fields merged in by
`favourite_fields()` (`:445-467`) — which reads all card metadata from the `local_dimensions`
MUC caches (`template_metadata_cache`, `competency_metadata_cache`, `plan_trail_cache`) and never
queries `customfield_*` or the File API itself. `plancard_layout` picks exactly one of the two plan
branches: `isvertical` → `PLN`, `ishorizontal` → `PLN-H` (`dataset_provider.php:904-905`).
Plan cards are built for the status bucket on screen; outside the active bucket every plan renders as
a plan card whatever its template's display mode, with a status chip, *View plan* on its pill and no
favourite star (`dataset_provider.php:262-288`, `:438-442`). Visual replica: the card screens of this
kit (`screens/plan-card-vertical.html` and `screens/plan-card-horizontal.html` for the two plan
layouts and their trail, `screens/competency-card.html` for the competency card, and
`screens/plan-status.html` for the status chip), shown as-is in light and dark.

**Settings affecting this screen:** `plancard_layout` (**vertical (default) / horizontal** — picks
the `PLN` or `PLN-H` branch wholesale, read twice: into the card payload at
`dataset_provider.php:873` and into the UI config at `:702`), `enable_trail_links` (off by default;
gates `PLN-TRAIL-LINK` / the `.clickable` class and therefore the `set_return_context` call),
`enable_favourites` (on by default, "never set" counted as on — gates the favourites pills, the
ghost card, the whole favourites-first two-phase load and the stars: with it off every card arrives
with `showfavourite` false, so `PLN-FAV` / `PLN-H-FAV` / `CMP-FAV` are not drawn). The four tag-filter settings
`enable_plan_tag1_filter`, `enable_plan_tag2_filter`, `enable_competency_tag1_filter`,
`enable_competency_tag2_filter` (each with a `*_displaymode` of tabs/dropdown) do not change a card's
appearance, but they read `tag1` / `tag2` straight off the card payload — the same two values that
feed `PLN-TAGS` / `CMP-TAGS` — via the `data-plan-tag1` / `data-competency-tag1` attributes
`renderCardItem` stamps on each `<li>`, so a tag that is empty on the card is also invisible to its
filter. Filter labels come from the custom field's own display name
(`dataset_provider::get_customfield_name()`, `:741-759`).
