# Field map — `PLN` / `PLN-H` / `CMP` · Plan cards, competency cards and the trail

The two card types are the whole visible payload of the block. Neither is server-rendered: the shell
`summary.mustache` ships only labels and config, `amd/src/filters.js` calls
`block_dimensions_get_block_dataset`, and `renderCardItem` (`filters.js:248-272`) renders
`block_dimensions/plan_card` or `block_dimensions/competency_card` through `core/templates` into an
`<li>` it builds itself. Every field in the three tables below comes out of
`classes/local/dataset_provider.php` — `build_plan_card()` (`:602-677`) and
`build_competency_card()` (`:818-867`) — which reads all card metadata from the `local_dimensions`
MUC caches (`template_metadata_cache`, `competency_metadata_cache`, `plan_trail_cache`) and never
queries `customfield_*` or the File API itself. `plancard_layout` picks exactly one of the two plan
branches: `isvertical` → `PLN`, `ishorizontal` → `PLN-H` (`dataset_provider.php:674-675`).
Visual replica: the card screens of this kit (`screens/pln-*.html` for the vertical and horizontal
plan cards and their trail, `screens/cmp-*.html` for the competency card), both shown as-is in light
and dark.

**Settings affecting this screen:** `plancard_layout` (**vertical (default) / horizontal** — picks
the `PLN` or `PLN-H` branch wholesale, read twice: into the card payload at
`dataset_provider.php:647` and into the UI config at `:502`), `enable_trail_links` (off by default;
gates `PLN-TRAIL-LINK` / the `.clickable` class and therefore the `set_return_context` call),
`enable_favourites` (on by default, "never set" counted as on — gates `PLN-FAV` / `PLN-H-FAV` /
`CMP-FAV` and the whole favourites-first two-phase load). The four tag-filter settings
`enable_plan_tag1_filter`, `enable_plan_tag2_filter`, `enable_competency_tag1_filter`,
`enable_competency_tag2_filter` (each with a `*_displaymode` of tabs/dropdown) do not change a card's
